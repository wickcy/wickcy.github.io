# 旅行照片与票根

照片只在所属旅行的 `photos.json` 中维护一份索引。相册导航页从同一份内容生成旅行票根入口，点击后才进入该次全部照片；城市档案关联到所属旅行。票根是衍生展示文件，不重复计数。

## 一张照片的内容

```json
{
  "id": "river-evening",
  "src": "/images/trips/your-trip/photos/river-evening.webp",
  "thumbnail": "/images/trips/your-trip/photos/river-evening-thumb.webp",
  "alt": "傍晚河面上的小船与岸边灯光",
  "caption": "天快黑的时候，再沿河走一段。",
  "cityId": "your-city-id",
  "featured": true,
  "ticketSrc": "/images/trips/your-trip/tickets/river-evening.webp",
  "width": 1600,
  "height": 1067
}
```

- `id`、`src`、`alt` 为必填。`alt` 描述真实画面，不猜地点、人物身份或拍摄日期。
- `thumbnail` 是面向列表的压缩缩略图，未提供时使用 `src`。`width`、`height` 记录原照片实际尺寸。
- `preview` 可为超高像素照片提供适合浏览的大图，查看器优先使用它；`src` 仍保留完整尺寸，通过查看器中的「打开完整尺寸」访问。
- `caption` 是可选说明，未提供时显示 `alt`；`cityId` 可关联已有城市 ID。
- `featured: true` 表示精选，单次旅行最多选择 3 张。页面兼容没有精选、1 张、2 张和 3 张。
- `ticketSrc` 指向已经制作完成的票根图片。没有票根时，相册入口使用精选或首张照片的缩略图；缺少缩略图则显示轻量占位，不加载完整大图。
- `ticketWidth`、`ticketHeight` 可记录票根实际尺寸，与照片的 `width`、`height` 分开。
- `/photos/` 每次旅行只显示一张相册入口卡，完整保留 1–3 张精选票根的比例；整张卡链接到 `/trips/{tripId}/photos/`，不在入口页输出全部照片或查看器。
- 单次相册采用无间隙的瀑布流，横竖图按原比例展示；说明叠在图底的 65% 黑色半透明条上，使用白字，长文字在照片墙显示两行，完整说明可在查看器阅读。
- `photos.json` 中的顺序用于查看器前后浏览。瀑布流按列从上到下、再到下一列排列，键盘焦点遵循同一顺序。桌面三列，手机两列，不需要布局脚本；已知宽高预留空间，缩略图懒加载，完整大图按需加载。

## 图片制作与公开范围

网站只放允许公开的照片副本。相机原始文件可自行留存，不建议直接放进仓库。发布前按用户意愿移除定位和 EXIF 信息，压缩照片并生成缩略图；不要把现有目的地参考图当作用户旅行照片。

`public/` 中的静态资源可以被直接访问。旅行设置为未发布，并不保护已经放入公开目录的图片；未允许公开的素材不要提交到公开仓库。

使用 `dy-travel-ticket-poster` 制作票根属于内容制作步骤，按用户真实照片、地点和说明生成静态成品，再把路径写入 `ticketSrc`。网站本身不调用图片生成服务，也不会用自动猜测的数据填补票根文字。

## 组件接口与检查

`src/features/gallery/Gallery.astro` 接收 `photos` 数组，以及可选的 `title`、`description`。
列表没有照片时显示空状态；有照片时支持原生对话框查看、前后浏览、左右方向键和 Esc，关闭后焦点回到打开照片的链接。
关闭 JavaScript 或浏览器不支持原生对话框时，照片链接仍可直接打开原图。

导航索引的检查命令：

```text
node src/features/gallery/gallery.test.mjs
```

修改相册后应检查票根进入对应旅行、手机排版、横竖图比例、1/2/3 张精选入口、图片加载失败以及键盘浏览；空相册继续显示空状态。

## 2026 年北京与济南照片导入

- 来源为用户摄影，北京 69 张、济南 29 张；顺序按文件名的拍摄时间排列，画面说明已逐张核对。济南旅行日期经用户确认采用 10 月 24–25 日。
- 原件与手机相册数据库留在 `tmp_photo/`；该目录已加入 `.gitignore`，不会进入构建或提交。公开文件用独立英文路径保存。
- `photos/` 按用户确认采用质量 94 的高质量 WebP，有损编码、保留每张照片完整分辨率，不裁切。来源为已清除手机私有附加数据的标准 JPEG 画面；编码时按原 ICC 色彩配置转换为 sRGB，公开副本不包含手机专用的编辑或附加成像数据。
- `thumbnails/` 长边最高 960px，WebP 质量 85，仅用于照片墙与封面；浏览相册时不预加载完整大图。超高分辨率大图仍可能较大，点击后才下载。
- 两张既有票根使用无损 WebP 保留 1170 × 1560 尺寸，分别关联天安门与趵突泉的真实来源照片，不重复计数、不重新生成。
- 所有公开副本移除 EXIF、XMP 与 IPTC（含定位和设备信息）；保留本地原件。景点参考图放在 `reference/`，其来源与许可记录在本次旅行的 `recommendations.json` 中。
- 本次 98 张照片原件合计 852,752,523 字节，高质量 WebP 大图合计 264,596,724 字节，减少约 69.0%；相比上一版清除附加数据的 JPEG 展示副本再减少约 32.0%。缩略图、票根与参考图另计。
- 济南有 1 张 12288 × 16320 的高像素照片，完整尺寸 WebP 约 33.1 MiB；另备长边 2560px 的浏览预览，避免手机打开时直接解码约两亿像素。完整尺寸仍可单独打开。
- 该高像素照片单独使用 Google 官方 cwebp 1.6.0（质量 94、method 3、segments 1、partition_limit 100）处理 WebP 头部容量限制，完整尺寸与解码均已检查。工具与处理脚本只留在被忽略的 `.local/`，不成为网站依赖。参数说明见 [官方 cwebp 文档](https://developers.google.com/speed/webp/docs/cwebp)。
